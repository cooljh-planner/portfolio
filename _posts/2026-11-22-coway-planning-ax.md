## 개요

"직렬 프로세스 관리에서 산출물 현행화 병목 해소로"

서비스기획자 AX 프로젝트는 팀장으로서 요구부터 반영까지 전체를 직렬 스테이지로 통과시키는 파이프라인 대신, 팀 실무에서 가장 많은 시간을 쓰고 자주 누락하는 **'주요 산출물의 지속적인 현행화'** 병목에 집중해 추진한 과제입니다. 상위 구조는 유지한 채 부분 변경 과업을 자동화하고 서비스 형상의 배경을 끝까지 추적한다는 원칙을 수립하고, 요구사항정의서 정본 기반의 **산출물 현행화 Skill**과 출처·ID 추적 체계의 설계·도입을 총괄하였습니다.

## 문제 정의

"산출물 간 맥락 단절과 수기 현행화의 누적 비용"

정기·비정기 배포마다 요구사항이 메일·Jira·회의록으로 흩어져 유입되면서 정책서, 기능정의서, 화면설계서(Figma), 위키를 수작업으로 맞추는 비용이 누적되었습니다. 실제로 팀 정기배포 검증에서는 배포 항목 대다수가 정책서에 누락되어 다수의 연관 문서를 일괄 보정해야 했습니다. 직렬 자동화는 앞단의 작은 수정이 뒷단 전체 재작업으로 번졌고, 산출물들이 공통 식별자를 공유하지 않아 AI가 변경 대상을 연결하기 어려웠습니다.

## 해결 방향

"정본 기반 병렬 현행화 Skill과 출처를 따라가는 추적 체계"

전체 공정을 직렬로 묶지 않고, 요구사항정의서를 정본으로 삼아 영향 문서를 병렬로 현행화하며 모든 변경에 출처를 남기는 실행형 Skill 체계를 수립해 팀 실무 프로세스에 정식 반영하였습니다.

### 1. 직렬 스테이지 해체와 정본 기반 병렬 현행화 Skill 설계

직렬 스테이지를 해체하고 요구사항정의서 정본(SSOT)을 기준으로 **요구 → 기능 → 화면·정책** diff 체인을 분석하는 현행화 Skill 구조를 설계·도입하였습니다. 수집·구조화·관계 분석·반영안·승인·반영 실행·보고 흐름에서 정책서·기능정의서·화면설계서 등 주요 기획 리소스별 반영안을 먼저 제시하고, 기획자의 단일 승인(HITL 최소화) 후 쓰기 도구가 연결된 리소스를 병렬로 갱신합니다. '분석은 결합, 쓰기는 독립' 원칙과 승인 시점 해시 고정을 적용해 범위 밖 변경을 막았습니다.

### 2. 산출물 간 맥락 연결을 위한 출처 추적 체계와 문서 ID 규칙

AI가 여러 문서를 넘나들며 문맥을 잃지 않도록 요구 건마다 발의일 기반 요건 ID를 채번하고, 모든 구조화 항목에 원문 인용과 출처를 필수로 붙여 근거 없는 내용을 게이트에서 차단하였습니다. 실제 문서의 요건 ID와 화면 ID 링크를 잇는 추적 뷰를 파생 산출물로 정착시키고, 팀 과제에서 요건·영향도 분석서·상위기획 명명 규칙과 절 단위 정책 ID 양식 및 업무 ID 기반 매핑·추적 기준을 표준화하였습니다.

### 3. 반복 검증 기반 Skill 고도화와 단계별 기획 Skill 연계

반복적인 고도화 과정에서 비참여자 적대적 검증과 결정론적 자체 테스트 기준을 수립하고, 릴리스마다 다수의 검증 에이전트를 투입해 주요 결함을 선제 제거하였습니다. 아울러 팀장으로서 팀원들이 제작한 요구사항 분석·상위기획·정책 정의 Skill 및 AI 판독 작성 표준을 통합 검토·조율하여 팀 단위 적용 기준을 확립하고 정식 운영에 안착시켰습니다.

## 회고 포인트

직렬 스테이지를 초기 설계 단계에서 키운 뒤에야 과감히 걷어 냈고, 완전 독립 병렬 역시 문서 간 정합을 깰 수 있어 관계 분석 단계를 보완했습니다. AI에게 문서 관리를 맡기기 전 출처·ID와 판독 표준이라는 데이터 구조를 먼저 세우는 일이 기획 조직 AX의 본질이었으며, 정식 도입된 현행화 Skill과 작성 표준을 팀 변경 건에 지속 적용하며 산출물 정합성과 기획 생산성을 높이고 있습니다.
